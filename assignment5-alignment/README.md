## TL;DR: 1.5B 参数下的“R1”推理能力演进

本项目在单卡 4090 (48G) 资源约束下，复现了类 DeepSeek-R1 的推理能力演进逻辑。通过对 **Dr.GRPO 算法的无偏适配** 与 **“白金级”数据治理**，成功验证了小参数模型在复杂逻辑任务上的涌现潜力与泛化边界。

#### 1. 核心实战战绩 (Verified Metrics)

- **MATH-500 潜力兑现**：Pass@1 从 Baseline 的 **14.4%** 提升至 **60.6%** (RL w/o std 变体)；其知识上限 **Pass@64 达到 93.6%**，几乎完全追平官方 Instruct 模型的 93.8%。

- **竞赛级逻辑跨越**：在 AIME 2024 中实现 **40.0%** 的 Pass@64 解决率；在 AIME 2025 压力测试下维持 **36.7%** 的 Pass@64 性能。

- **全梯度难度对齐**：基础任务 GSM8K Pass@1 达到 **80.6%**；中程推理任务 AMC12 Pass@1 从 2.4% 跃升至 **36.1%**。

  

#### 2. 核心技术 Insight

- **Dr.GRPO 无偏适配**：针对单卡小 Batch 场景，通过**移除标准差归一化 (std-norm)** 解决了奖励信号震荡问题。实验显示，该改进在高难度 AIME 任务中使采样上限性能显著提升 (40.0% vs. 标准 GRPO 30.0%) 。

- **数据极简主义**：摒弃万级噪声数据，仅通过 **3,000 条逻辑蒸馏的“白金样本”** 完成 SFT 冷启动。通过调整 Loss Mask 策略诱导模型**自主触发 `<think>` 标签**，实现了从行为模仿到逻辑内化的突变。

- **推理“内化压缩”规律**：量化观测到思维链长度呈 **“倒 U 型”演变** (~1102 → ~817 tokens) 。RL 作为逻辑剪枝器，在不损知识上限的前提下将推理成本降低约 **25%**。

  

#### 3. 科学发现与病理诊断

- **推理留存率 ($\Delta R$) 框架**：提出以 AIME 24 vs. 25 作为“自然实验”场，定义“留存率”指标评估模型逻辑纯度。
- 数据泄露诊断：观察到AIME24和25测试中baseline模型的反常表现，用推理留存率衡量Qwen模型在AIME24和25的表现差异，并通过一个具体的求解案例与两个测试集上正确样本的分布差异确认了数据泄露的大概率存在。
- **归纳摩擦 (Inductive Friction) 假说**：推导并验证了算法无偏性在不同分布下的代价——Dr.GRPO 虽然在稀疏奖励区（难题）表现优异，但在密集奖励区（易题）因探索方差较大导致 Pass@1 略有回撤。

## Chapter 1 摘要
<a id="section-1"></a>

### 1.1 **项目概述**

<a id="section-1-1"></a>

本项目在单卡4090 (48GB VRAM) 上成功复现了 类 DeepSeek-R1 的推理能力演进流程 。我们以 **Qwen-2.5-Math-1.5B** 为基座模型，通过利用`HuggingFaceH4/Bespoke-Stratos-17k`**构建“白金数据”监督微调 (SFT)** 与 **GRPO 强化学习算法**，有效引导出了1.5B 参数规模模型的数学推理能力。

实验证明，通过极简的高质量 SFT 冷启动与针对性的 RL 算法改进，小参数模型不仅能习得严谨的 XML 格式规范，更能在逻辑链条上实现从“机械模仿”到“内化压缩”的质变。



### 1.2 **核心战绩**

<a id="section-1-2"></a>

**性能突破**：MATH-500 从 14.4% 提升至 60.6%，Pass@64追平官方模型(93.6% vs 93.8%),  在AIME25上实现36.67%的Pass@64, 并在k <= 16内表现持平甚至超越官方模型。

**数据效率**：通过数据蒸馏，以 **3,000 条样本** 胜过万级噪声数据，实现 88% 的训练减量与 2.4 倍的精度增益。

**采样阶跃**：RL 后的 $k=1$ 表现追平 SFT 的 $k=4$。



### 1.3  **技术策略与算法适配**

<a id="section-1-3"></a>

- **Dr.GRPO 算法的工程实践**：
  
  - **适配逻辑**：针对单卡小 Batch 场景，复现了 Dr.GRPO 中去除标准差归一化与动态长度归一化的策略，以尝试解决标准 GRPO 在极端资源受限下的训练波动问题 。
  - **实证发现**：实验显示，在 AIME 2024 等高难度任务中，Dr.GRPO 变体对比标准 GRPO 表现出了更高的峰值准确率（AIME24 40.0% vs 30.0%）与更稳健的收敛趋势。
  
- **单卡训练优化**：
  
  - **权重进程内同步**：针对 **On-policy 强化学习**频繁采样的特性，通过**内存级权重同步机制** 替代了传统的磁盘 IO 中转，确保了模型在单卡 4090 环境下的高效迭代。
  - **分批概率计算 (batched LogProbs)**：将引用模型的生成概率计算微批次化，显著缓解4096序列长度训练下采样旧策略时的瞬时显存峰值。
  
- **推理演化行为洞察**：
  
  - **思维链“倒 U 型”演化**：量化观察到了 CoT 长度从“直觉”到“模仿”再到“内化压缩”的动态演变（~1102 $\rightarrow$ ~817 tokens），揭示了 RL 带来的逻辑密度提升。
  
    

### 1.4  奖励机制与评估标准

<a id="section-1-4"></a>

项目中的评分框架基于 **CS336 Assignment 5** 的官方框架构建，通过集成成熟的数学校验逻辑，重点探究 1.5B 模型在强化学习中的行为演化。

#### **A. 核心评分框架**

模型必须在满足硬性格式约束的前提下，才有机会获得正确性奖励 ：

- **格式对齐 (Format Reward):** 响应必须遵循标准的 XML 标签闭合协议 。
- **结果校验 (Answer Reward):** 采用“全有或全无”的硬约束评分。仅当模型在规定格式内输出正确答案时，方可获得奖励分值。



#### **B. 评估引擎说明**

**[注] 以下模块集成自 CS336 官方基架代码，确保了与业界主流推理模型评测标准的一致性**

- **数学校验引擎:** 结合了 `MathD` 规范化与 `SymPy` 符号代数检查，通过 `sympy.simplify` 识别数学上等价但表达形式不同的解。

- **LaTeX 鲁棒处理:** 采用 `math_verify` 和 `latex2sympy` 自动剥离单位（如 `degree`, `cm`, `mile`）及处理混合分数（如 `7 3/4` 转为 `7+3/4`），确保模型不会因微小的格式扰动而丢失奖励。

- **重复性检测 (`repeatness`):** 内置基于 **后缀数组 (Suffix Array)** 与 **LCP (最长公共前缀)** 的字符串自相关算法。当逻辑循环率超过 0.2 时触发惩罚

  

#### **C. 行为干预机制**

针对观测到的 "Length Hacking" 现象，我们在 RL 阶段引入了干预 ：

- **非线性长度惩罚 (`length_penalty`):** 针对超过 3,072 Tokens 的冗长响应实施非线性惩罚（每 100 Tokens 扣除 0.02 奖励分），实现了约 25% 的推理密度提升 。

  

#### **D. 格式容错预处理**

为了缓解 1.5B 模型在训练初期对 XML 标签边界控制不精确导致的奖励丢失，本项目在调用官方评测逻辑前引入了自定义的鲁棒化处理层：

- **空格/换行对齐：** 自动识别并修复模型输出中常见的格式微瑕，如 `</think><answer>`（缺失空格）或 `</think>\n<answer>`（多余换行）。

- **设计动机：**在 GRPO 采样过程中，这些微小的 Token 差异不应影响对核心逻辑能力的评估。通过预处理，我们将 **“格式对齐”** 的学习门槛从“字符级匹配”放宽到了“语义标签匹配”，有效提升了训练初期的有效信号捕捉率，避免了模型因琐碎的格式错误而陷入无法收敛的困境 。



### 1.5 评测协议与口径统一性

<a id="section-1-5"></a>

为了确保 Baseline、SFT、RL 模型与官方 Instruct 模型之间的公平对比，本项目构建了两套对齐的评测流水线，核心逻辑如下：

#### **A. 统一的 Pass@K 评估逻辑 (`evaluate_passk.py`)**

- **带早停的迭代采样 (Early Stopping):** 考虑到资源因素，脚本实现了高效的 早停Pass@K 逻辑。对于每一道题目，若在第 $i$ 次尝试中获得正确解（Reward=1.0），则立即停止后续采样。

- **计算效率:** 统计 Pass@1 到 Pass@K 的解决率变化趋势，能够清晰观测模型从“博学但犹豫”到“自信且精准”的分布锐化过程。

  

#### **B. 适配模型特征的 Prompt 策略**

针对不同来源的模型，我们严格遵循其训练时的分布协议：

- {官方Baseline预训练基座模型}: 作为对比，使用自定义XML模板，以测试zero shot下预训练模型的指令遵循能力。

- **自研模型 (SFT/RL):** 使用自定义 XML 模板（`r1_zero.prompt`），并配合 `robust_reward_fn` 进行容错解析。

- **官方 Instruct 模型:** 动态加载对应模型的 `tokenizer.apply_chat_template`，确保对比基准处于其官方推荐的最佳性能状态。

  

#### **C. 核心判定逻辑的对齐**

尽管输出格式各异，但所有模型共用一套**数学判定引擎 (`grade()`)**：

- **对 RL 模型:** 采用 `r1_zero_reward_fn`，强制检查 `<think>` 和 `<answer>` 标签的完整性。

- **对官方 Instruct 模型:** 采用 `qwen_instruct_reward_fn`。该函数不强制要求 XML 标签，而是直接提取 `\boxed{}` 内容进行数学一致性校验，确保不因格式差异惩罚官方模型的数学能力。

  

#### **D. 推理参数配置**

所有评测均在 **vLLM** 引擎上完成，以保证推理效率与显存占用的最优平衡：

- **采样常规设置:** Temperature=0.7, Top-p=0.95, Max_tokens=4096。
- **停止符设置:** RL 模型使用 `</answer>`或`<|endoftext|>` 停止，Instruct 模型适配 `<|im_end|>` 与 `\n\n\n` 等官方推荐标识符。

## Chapter 2 训练流水线设计：从行为模仿到逻辑内化

<a id="section-2"></a>

本项目采用两阶段演进策略，旨在平衡 1.5B 小参数模型的“格式对齐”与“推理潜力激发”。

### 2.0 Prompt设计

<a id="section-2-0"></a>

![prompt](asset/rendered_prompt.png)
<p align="center">图1 为复现R1-zero构建的System Prompt</p>



Prompt 的设计在本复现中并非简单的文本提示，而是**RL训练的“契约”**。我们构建了一个**强结构化（Structurally Enforced）**的 System Prompt，其核心包含两个维度的约束:

1. **拓扑约束 (Topological Constraint)**：强制模型输出 <think> 和 <answer> 标签对。这不仅是为了格式整洁，更重要的是为后续的 **Format Reward** 提供了可计算的**锚点（Anchor）**，使奖励模型能精确区分‘推理流（CoT）’和‘最终结论’
2. **思维触发 (Reasoning Trigger)**：通过指令显式要求 *'think about the solution process'*，在 SFT 阶段诱导模型生成长思维链，从而为 RL 阶段的**GRPO**提供了可被优化的**搜索空间（Search Space）**。



这种‘硬约束’Prompt 是 R1 能够在不依赖**大量**符合think tag xml标签的结构化数据进行微调的情况下，涌现出自我反思能力的第一推动力。



### 2.1 **阶段一：格式对齐与冷启动**

<a id="section-2-1"></a>

SFT 阶段并非旨在向模型注入新知识，而是通过**行为克隆**为后续的强化学习提供高质量的“逻辑种子”与“风格基底”。

- **核心目标**：使基座模型学会 `User/Assistant` 对话模板，并熟练掌握 `<think>...</think>` 与 `<answer>...</answer>` 的 XML 标签规范

- **数据驱动的消融策略**：
  - 通过对 1.7 万条原始数据进行“去毒”处理，剔除了导致模型习得“啰嗦”和“死循环”的长上下文样本。
  - 最终采用 **SFT v6（3,000 条白金样本）**，通过格式清洗和逻辑蒸馏（强制答案极简），实现了 **44.10%** 的准确率，为 RL 阶段提供了最“诚实”的起点。
  
- **工程配置**：采用 Full Finetuning 模式，设置最大序列长度为 4096，确保逻辑链条的完整性。

- **协议自触发机制**：通过调整 SFT 阶段的 Loss Masking 策略，将 `<think>` 引导符从“Prompt 引导区”移入“Loss 计算区”。这一改进强制模型在没有任何格式暗示的情况下，从零开始自主预测思考链的起始标识，实现了从“被动接收指令”向“主动触发逻辑协议”的质变，旨在验证标签预测的契约深度对复杂推理潜力的启发作用。

  

### 2.2  **阶段二：逻辑强化与演进**

<a id="section-2-2"></a>

强化学习阶段旨在通过**组内相对优势 (Group Relative Advantage)** 激发模型的自我修正能力，使其从“机械模仿”进化为“深度推理”。

- **算法选择与适配**：

  - **复现 Dr.GRPO**：针对单卡（RTX 4090 48GB）小 Batch 训练不稳定的痛点，我们参考 Sea AI Lab 的研究，移除了 Advantage 计算中的**标准差归一化**与**动态长度归一化**。

  - **优势**：相比于标准 GRPO，Dr.GRPO 在高难度任务（如 AIME）中表现出更强的鲁棒性，有效避免了小规模采样下的梯度方向偏移。

    

- **多维度奖励函数设计 (Reward Designing)**：
  - **严格 XML 耦合奖励 (Coupled Reward Logic)**：
  
    - **逻辑**：奖励计算完全依赖于 XML 解析器。若 `<think>` 或 `<answer>` 标签格式不规范，系统将直接判定为“无法提取答案”并给予 **0 分** 的 Answer Reward 。
    - **意义**：这建立了一个“全有或全无”的硬约束环境。模型必须首先内化格式规范，才有机会通过正确逻辑获取更高的奖励分值，从而实现了格式规范与逻辑推理的协同阶跃式进化。
  
  - **长度敏感型惩罚 (Length-Aware Penalty)**：
  
    - **策略**：为超过 **3,072 Tokens** 的响应引入与长度呈正相关的非线性负奖励。
    
    - **设计初衷与逻辑优化**：
      - **现象观测**：实验数据表明发现，格式错误样本的 Token 长度普遍逼近 4,096 的物理上限（均值 > 3,500）。
      
      - **算法偏见**：这种“长而错”的现象揭示了标准 GRPO 在处理负样本时存在的**长度偏差 (Length Bias)** 风险。当模型因逻辑死循环而无法输出 EOS 终止符时，极长的无效生成不仅耗尽了计算资源导致物理截断 ，还可能在组内优势计算中因长度与奖励的非良性耦合而产生误导信号 。
      
      - **干预效果**：通过引入 **3,072 Token 惩罚项**，我们对超长响应施加了显著的负向激励 。这一举措有效遏制了模型通过无限逻辑循环来逃避得出结论的 **Length Hacking** 行为 ，迫使模型在安全长度区间内进行“内化压缩”，从而实现了更高的逻辑密度与更稳健的推理行为 。
      
        
  
- **稳定性机制**：引入 PPO 风格的 **Trust Region Clipping**，在单卡环境下无需持续运行昂贵的reference模型即可维持训练稳定。

  

### 2.3 **行为演化观测**

<a id="section-2-3"></a>

通过这一流水线，我们观察到了模型推理行为的质变：

- **“去肥增肌”演化**：RL 阶段充当了逻辑剪枝器，剔除了 SFT 阶段因模仿而引入的冗余复读，将平均思维链长度从 ~1,102 优化至更具逻辑密度的 ~817 Tokens 

- **效率与精度同步提升**：GRPO 不仅将 Pass@1 准确率推至 **83.4%**，更在保持高精度的同时使推理成本降低了约 25% 。

## Chapter 3 SFT 数据治理

<a id="section-3"></a>

**基于数据的核心发现：**

**训练效率阶跃**：SFT v4 (Platinum) 仅需 3,000 步即可在 MATH 上取得 44.1% 的准确率 ，相比 v1 版本，在减少 88% 训练量的同时，准确率提升了约 2.4 倍 。

**Epoch 的负面效应**：对比 SFT v3 的演化（Epoch 1 -> 2），虽然准确率提升了 9%，但正确样本的中位数长度从 1374 膨胀至 1520 。这表明持续训练会导致模型习得“冗长 = 正确”的偏见，而非真正的逻辑进步。

**格式错误与物理截断的强相关**：数据记录显示，格式错误样本的长度中位数（3931）极度接近 4096 的上限 。这为我们后续在 RL 阶段引入 **3072 Token 长度惩罚** 以遏制 Length Hacking 提供了量化支持。



实验通过对1.5B小参数模型的系统性消融研究，证实了核心论点：**数据的纯度（正确性与格式规范）远比数量重要。** 以下是SFT数据策略从“粗放”到“精细”的完整演变路径：

##### 1. 早期探索：噪声干扰与长程迷失 (v1 - v2)

- **初始状态 (v1)：** 采用随机抽取的5k数据（含噪）。模型不仅学习了推理，也由噪声数据学会了冗余废话，导致输出过长而被物理截断，准确率仅18.00%，且格式错误率极高。

- **长度过滤尝试 (v2)：** 为解决截断问题，简单过滤掉长度大于4k的样本。结果引发了**“死循环现象”**（如反复输出"Wait..."），准确率跌至15.64%。这表明单纯截断长样本会导致模型在长程推理中迷失方向。虽然通过引入1.05的重复惩罚强行提升了准确率（至45.54%），但这掩盖了模型本身未能学会“何时停止”的缺陷。

  

##### 2. 格式规范化：截断与过拟合的博弈 (v3)

- **格式清洗 (v3 E1)：** 引入reward_fn评分，仅保留格式干净（Tag完整）的样本。模型具备了解题能力（准确率回升至40.02%），但缺乏停止机制。数据显示，格式错误样本的中位长度逼近4096上限，说明大多数错误是因未预测到EOS导致的**物理截断**。

- **增加训练 (v3 E2)：** 试图通过增加Epoch提升效果，虽准确率提升至49.48%，但出现了**“风格过拟合”**。正确样本长度从1374膨胀至1520，模型习得了“冗长=正确”的错误偏见，变得更加啰嗦，且截断风险依然高企。

  

##### 3. 结构重塑与逻辑内化：质的飞跃 (v4)

- **结构化分离 (v4.1)：** 实施“思考清洗”与“答案蒸馏”。剔除思考过程中的答案泄露，并强制精简<answer>标签内容。这一强约束使模型学会了“思考”与“表达”的明确界限，生成的正样本极其干净。

- **指令自触发 (v4.2 - 最终选用版)：** 进一步调整Loss计算策略，将<think>起始标签纳入Loss计算。这一微小的改动将模型从“被动接受Prompt引导”转变为“主动预测思考标签”，极大地强化了思维逻辑的内化与自发触发能力。
  
  - **最终成效：** SFT v4.2仅需 **3,000步** 训练，便在MATH上取得了 **44.10%** 的准确率。相比v1版本，在 **减少88%训练量** 的同时，准确率提升了约 **2.4倍**，且平均长度大幅优化至2,158，实现了高效与精准的双重突破。
  
    

##### 4. 后续展望 (v5)

鉴于v4版本清洗过于极致，且SFT数据来源单一，导致清洗出的数据缺乏内容和形式上的多样性，模型泛化性不足（易产生模式崩塌）。

v5 计划重新引入精选的优质长推理数据，包括推理风格多样化和来源于难度多样化题目的规范化CoT，以提升泛化能力与多样性表现。

### 3.3 惯性与语义的冲突——Prompt修正实验

##### 结果解析：一场关于“顺应”与“对抗”的博弈

上述六组实验结果，实质上揭示了大模型在微调过程中，**预训练本能（Nature）** 与 **后天对齐（Nurture）** 之间的深层博弈。从基座模型的角度出发，可以看到其对Prompt中的\n和空格的区分极为敏感，当提示词中的</think>和<answer>之间被\n这个预训练中语境割裂意味极重的token割裂开来时，预训练的文本补全本能难以捕捉到两者间的关联，便难以建立起好的指令遵循能力。相比之下，空格作为一个软过渡的token就能让模型更好的捕捉到两个tag之间的衔接关系。

##### 1. 顺势而为：为什么“原版SFT”是版本答案？

**原版 SFT (Prompt空格 + Data换行)** 之所以能取得 **51.6%** 的最高分，是因为它巧妙地达成了一种“认知分工”：

- **输入端（Prompt）：** 保留空格。这顺应了 Base Model 对自然语言“流连贯性”的偏好。模型读到空格时，注意力机制能更顺畅地将 System Prompt 的语义传递给后续生成的 Token。
- **输出端（Data）：** 强制换行。这利用 SFT 的强监督信号，强行建立了结构化的输出规范。
- **结论：** 这是一种**“外圆内方”**的策略——对输入宽容（符合直觉），对输出严格（符合规范）。这种策略最小化了模型处理 Prompt 时的认知负担。

##### 2. 过犹不及：为什么“改版SFT”反而变弱了？

**改版 SFT (全链路换行)** 试图在逻辑上追求绝对的“训练-推理一致性”，结果却遭遇了滑铁卢（最高仅 46.2%）：

- **对抗归纳偏置：** 当我们把 Prompt 中的空格也改为换行，我们实际上是在强迫模型去**“遗忘”**它在预训练中学到的通用语言规律（即：空格是连接词，换行是断句）。
- **参数浪费：** 模型被迫分配宝贵的参数容量去适应这个两个逻辑相同的tag用换行隔开的“反直觉”的 Prompt 格式，而不是专注于数学推理本身。这就是所谓的**“归纳摩擦 (Inductive Friction)”**。

##### 3. 鲁棒性的悖论：噪声即抗体

对比 **原版SFT** 和 **改版SFT** 在面对“原版Prompt（空格）”时的表现（51.6% vs 20.0%），我们可以看到：

- **原版SFT** 因为训练时存在“Prompt空格 vs Data换行”的错位，这种错位充当了一种**天然的数据增强（Data Augmentation）**。它教会了模型：“无论 Prompt 怎么写，我都要按标准格式输出”。

- **改版SFT** 在温室中长大，从未见过这种不一致，因此极度脆弱，丧失了泛化能力。

  

##### 结论

在小参数模型的工程实践中，**最好的微调策略不是去“纠正”基座的直觉，而是去“利用”它。** 哪怕这在人类看来包含一点逻辑上的小瑕疵（如 Prompt 中的空格），只要它符合模型的概率分布本能，就是提升性能的关键支点。



### 3.4 SFT阶段结论：一场精密的“行为外科手术”

<a id="section-3-4"></a>

综合以上三个层面的系统性消融实验，我们可以得出结论：对于1.5B这样的小参数模型，监督微调（SFT）阶段的核心逻辑并非传统的**“知识注入”**，而是一场旨在**“激活潜力”**与**“塑造行为”**的精密外科手术。这一阶段的成功，为后续强化学习（RL）算法的高效探索和潜力兑现奠定了坚实的基础。其核心逻辑可被提炼为以下三点：

1. **数据的纯度重要性远超数量:** 我们的数据策略演变路径（v1至v4）明确证实，对于小参数模型，噪声数据不仅无益，甚至有害。通过将数据集从5k含噪样本极致蒸馏至3k“白金”逻辑样本，我们不仅将训练量减少了88%，更实现了**从18.0%到44.1%的准确率飞跃**。这揭示了SFT的核心作用是提供一个**清晰、无歧义的“行为范本”**，而非知识的堆砌。
2. **格式即协议，纪律是基石 :** SFT的核心任务是为模型建立一套**高度机械化、可预测的输出“肌肉记忆”**。如SFT前后格式对比所示，通过强制的格式清洗与答案蒸馏，模型将 </think>\n<answer>\boxed{...}</answer> 的结构内化为一种行为协议。这不仅是为了输出的整洁，更是为后续强化学习（RL）阶段提供了**稳定、可解析的奖励锚点**，从根本上解决了奖励信号的归因难题，是逻辑链条得以“内化压缩”的先决条件。
3. **顺应而非对抗，化“摩擦”为鲁棒 :** “Prompt空格 vs. Data换行”的实验揭示了深刻的“**归纳摩擦 ”现象**。最佳策略并非强迫模型在输入端（Prompt）违背其预训练本能（Nature），而是**顺应其“阅读偏好”，同时在输出端（Data）强力塑造其“行为规范”（Nurture）**。这种“外圆内方”的策略不仅最小化了模型的认知负担，其固有的“指令-数据”错位甚至充当了一种天然的数据增强，显著提升了模型对微小扰动的泛化能力和鲁棒性。

## Chapter 4 强化学习算法思辨：无偏估计与泛化性的博弈



### 4.1 引言：1.5B模型的泛化困境与算法选择

SFT阶段的成功，证明了即便是1.5B这样的小参数模型，也能通过高质量的数据学会模仿，掌握严谨的格式与初步的思维链。然而，模仿并非真正的推理。为了激发其自我修正与逻辑探索能力，我们引入了强化学习（RL）阶段。

此阶段的核心挑战是双重的。首先，我们必须正视 **1.5B模型的内在容量局限**：它不可能像百亿、千亿级模型那样穷尽所有知识，其性能高度依赖于对核心逻辑的有效压缩与泛化。其次，我们的训练数据 `Bespoke-Stratos-17k`本身是**高度有偏**的，它集中于高难度竞赛题，形成了一个“专才”训练环境。

这两个限制共同指向了一个尖锐的矛盾，并在我们的实验中催生了一个关键的反常现象：旨在提供更稳定、无偏信号的Dr.GRPO算法，在引导这个“**容量有限的专才模型**”去应对全面的测试集时，其泛化能力反而不如标准GRPO。理论上的算法优势，在实践中似乎变成了泛化能力的“枷锁”。

本章将深入探究这一现象，剖析RL算法设计、小模型的能力边界、与有偏数据环境三者间的复杂交互，旨在回答一个核心问题：**对于一个小参数模型，当训练数据存在显著偏差时，什么样的RL策略才能最大限度地激发其宝贵的泛化潜力？**



### 4.2 实验设计：有限容量下的有偏训练与全面评测

我们的实验设计旨在严格评估一个**1.5B小参数模型**，在接受了**专业化、高难度训练**后，向一个**全面、多层次的测试环境**进行泛化的能力。这一设计旨在揭示小模型在知识迁移过程中的脆弱性，并考察不同RL算法对其泛化边界的影响。

**训练数据的偏差与小模型的敏感性：**

训练数据源自 `Bespoke-Stratos-17k`，其高难度的内在偏差对1.5B模型提出了严峻考验。由于容量有限，模型无法“记忆”所有解法，必须努力从这些难题中归纳出可迁移的逻辑模式。这种训练环境迫使模型进行高强度的“逻辑压缩”，但也极易导致其对训练数据的分布产生**过拟合**，从而损害在分布外任务上的表现。

**评测体系的全面性与基线预期：**

我们构建了一个三梯度评测矩阵，以全面衡量模型的泛化能力。特别重要的是，我们为每个梯度的测试集都建立了**Baseline模型的性能基准**，以校准我们对一个未经优化的1.5B模型的初始预期：

- **基础能力层 (GSM8K):** 测试模型在解决了复杂问题后，是否还能保持对简单逻辑的**基础稳定性**。这是对知识“向下兼容”能力的检验。
- **核心能力层 (MATH, AMC12):** 作为**泛化能力的核心观测区**。我们预期模型在此会有显著提升，但由于其容量限制和训练偏差，可能难以企及大模型的性能高度。
- **知识上限层 (AIME):** 难度分布与训练集最接近，用于探测模型在“舒适区”内的**知识天花板**。即便在此，由于1.5B模型的容量瓶颈，我们也预期其性能会存在一个难以突破的上限。

**评估指标设置：**

我们选择使用 `Pass@k` 指标，因为它能精细地刻画小模型的学习状态：

1. **Pass@1** 反映了模型的**收敛能力**——它能否稳定地将学到的知识转化为首选的正确答案。
2. **Pass@k 曲线** 则揭示了模型的**潜力边界**——在其有限的参数空间内，究竟“蕴藏”了多少知识。

## Chapter 5  泛化真相：基于“推理留存率”的行业多维诊断

### 5.1 AIME 24 vs. AIME 25: 一个揭示泛化真相的“自然实验”

对于一个1.5B的小参数模型而言，其性能在面对高难度基准测试时出现下滑，是反映其内在能力局限的正常预期。然而，真正引人深思的并非这一普遍性的衰减趋势，而是在 **AIME 2024 与 AIME 2025 这两个数据集之间，模型表现出的显著性能差异**。

**最强有力的证据来自于Baseline模型（即未经任何SFT/RL微调的Qwen-2.5-Math-1.5B）的表现：**

- 从[**表3**](#table3-anchor)中可以清晰地看到，Baseline模型在AIME 2024上的Pass@64达到了**13.3%**。

- 相比之下，它在AIME 2025上的Pass@64仅为**3.3%**，两者相差整整**4倍**。

  

一个未经任何针对性微调的模型，为何在理论难度相当的两个测试集上表现出如此悬殊的差异？这引出了两个主要的**竞争性假说**：

**假说一（数据污染假说）：其预训练数据中已经包含了AIME 2024的题目或高度相似的解题讨论，而AIME 2025则是其从未见过的全新数据。**

**假说二（数据分布适配假说）： AIME 2024的数据分布（例如，题目类型、所需知识领域）可能偶然地、系统性地比AIME 2025更适合Qwen-Math系列模型的“能力甜点区”**。

为了探究哪个假说更具解释力，我们进行了一系列外部证据的检索与分析。



### 5.2 指标构建：推理留存率的定义与经济学释义

#### 5.2.1 推理稳定性指标设计

为了系统性地检验“数据污染”假说，我们需要一个能够科学地量化模型在“已知”（AIME 24）与“未知”（AIME 25）数据集之间性能稳定性的指标。一个核心的挑战在于，AIME 2024的性能指标本身可能已经因潜在的数据污染而成为一个**有偏的估计量**。

这类似于经济学和社会科学中著名的**古德哈特定律（Goodhart's Law）**：*“当一个度量本身成为目标时，它便不再是一个好的度量。”* 如果模型在预训练时已将AIME 2024的数据作为优化目标，那么其在该数据集上的高分则无法完全代表其真实的推理能力。

因此，基于Perf_24的简单度量，如**绝对性能差异 (Perf_24 - Perf_25)**，会因**基数效应**而产生误导，无法在不同模型之间进行公正的比较。

为了解决这一问题，我们借鉴了经济学中评估**资产保值能力**的思路，将模型在AIME 2024上展现的能力视为一种“初始价值”，并衡量其在AIME 2025这个新环境中能够“留存”下多少。我们为此定义了一个核心度量指标——**“推理留存率”**。

- **计算方式：** 留存率 = Perf_25 / Perf_24
- **经济学释义：** 这个指标在概念上，等同于衡量一项 **无形资产** 在经历了一个周期的市场变化后，其 **剩余价值与初始价值的比率** 。一个高留存率，意味着这项“知识资本”的 **折旧率低** ，其内在价值是稳固且可迁移的。反之，一个低留存率，则意味着其初始的高价值很可能只是泡沫，无法抵御真实的市场考验。

为了更精细地诊断这项“知识资本”的不同层面，我们进一步将其分层为两个指标：

- **Greedy 留存率 (Pass@1):**
  - **经济学类比：** 这可以看作是衡量企业**“核心业务的运营效率”**的稳定性。它反映了模型最常用的、最自信的“生产线”（推理路径）在面对新市场时的保值能力。
- **Upper 留存率 (Pass@16):**
  - **经济学类比：** 这更像是衡量企业的 **“总资产价值”** 或 **“长期潜力”** 的稳定性。它反映了模型全部“知识储备”的鲁棒性，即使这些储备没有被高效地利用。

基于上述图表，我们可以观察到留存率指标所揭示的，关于当前大语言模型（LLMs）内在稳定性的一些核心规律。

1.  **基于推理能力的“马太效应”：强者愈稳，弱者愈脆**

	从表4和表5的数据分布来看，模型的留存率与其基础性能（准确率）呈现出显著的“强者恒强”趋势，性能分化严重。

- **精英模型的“价值锚定”**：以 OpenAI o1-mini 和 DS Distill 32B 为代表的高性能模型，其“Greedy留存率 (Rg)”不仅没有衰减，反而大幅超越100%，展现出强大的“泛化红利”。同时，其“Upper留存率 (Ru)”也高度收敛于100%的稳定线，表现为一种“资产的良性巩固”。

- **底层模型的“能力蒸发”**：处于性能基座的底层模型（如 DS-Math-7B-RL），其留存率常常表现为断崖式的 0%（能力未涌现），或巨大的价值波动。这说明其推理路径极度脆弱，如同“原始账面价值”般，稍有扰动便会“价值归零”。

- **结论**：这揭示了留存率的偏差值 **ΔR = |R - 100%|**，实际上是衡量模型推理逻辑是否“内化”为稳定结构的核心负向指标。偏差越大，模型的内在逻辑越脆弱。

  
2. **参数规模的“压舱石”效应：规模提升带来稳定性收敛**

	以 Qwen2.5 系列为例，我们可以观察到随着参数规模（7B $\to$ 32B $\to$ 72B）的增长，留存率展现出的“收敛动力学”：

- **Greedy留存率 (Rg) 的“降噪”**：Qwen2.5-7B-I 的 *Rg* 为 60.4%，表现出较大的不确定性。而 32B 和 72B 尽管存在架构红利带来的溢价（*Rg* 分别为 180.2% 和 150.4%），但其搜索上限 *Ru* 表现出极强的稳定性（104.1% 与 98.5%），显示出噪音被有效抑制。
- **推理空间的“确定性”增强**：参数量越大的模型，其能力上限 *Ru* 越接近 100% 的理想稳定线。这说明大参数模型形成的推理“解空间”更加致密，对样本扰动的容忍度和鲁棒性也更高。



3. **时间维度的“范式演进”：从“混沌探索”到“逻辑求稳”**

	从 2024 年 2 月到 2025 年 1 月的时间轴上看，模型分布经历了从左下角向“100% 理想稳定线”集群移动的过程：

- **早期阶段**：2024 年上半年的模型（如 Llama-3.1-70B-I）多处于 50% 以下的低留存率区域，推理能力表现出高度的 OOD（分布外）脆弱性。

- **后强化学习时代**：2024 年 9 月后的推理模型（o1 系列、Qwen 数学系列、DeepSeek 蒸馏系列）开始在 70%-100% 区间密集分布。

- **演化本质**：时间轴上的向心力反映了行业后训练技术（Post-training）的共同取向——即牺牲不可控的性能爆发，追求可预测、可复现的逻辑稳定性。





### 5.4 统计动机：基于推理能力本源的二重性假设

基于上述分布特征的分析，我们提出一个核心假设：**“推理准确率”与“泛化稳定性”** 本质上是 **模型内在推理能力** 的一体两面。

- **准确率**衡量的是模型推理逻辑的**深度与覆盖度**；
- **稳定性（留存率）** 衡量的是模型推理逻辑的 **纯度与独立性**。

我们预设：真正的“本源推理能力”应当表现为准确率与稳定性的高度正相关——即逻辑越本质，其对题目分布的依赖就越小，表现就越趋于稳定。

**坐标系解读：**

- **X轴**是**模型发布时间**，**紫色虚线**标记了**“AIME 24考试日”**，它如同一道分水岭，将图表划分为“污染前”与“污染后”两个时代。

- 每一个**圆圈/箭头**代表一个模型。**圆圈的大小**代表参数量。**箭头的演化路径**，则动态地展示了从Greedy起点到Upper终点的“采样平滑效应”

  

##### 5.4.3.1 Greedy留存率 (Rg)：核心策略的“压力测试”

Rg (Pass@1的留存率)衡量的是模型**最自信、最收敛的核心策略**，在面对从“已知”（AIME 24）到“未知”（AIME 25）的环境剧变时，其表现的稳定性。

- **观察：** 表4和图X显示，绝大多数模型的Rg都显著偏离100%。一部分模型（如Llama-3.1）远低于100%，而另一部分（如Qwen2.5-32B）则反常地远高于100%。同时，在Greedy留存率的表现上，最好的三个模型依次为**OpenAI o1-mini**，**DS-Distill-32B**和**Qwen2.5-Math-72B-I**
- **推论：** 这有力地证明，**Pass@1作为一个评估指标，其本身是高度不稳定的**。它极易受到模型**“策略偏见”**（例如，过拟合了AIME 24的某种范式，导致Rg<100%）或**“随机噪声”**（例如，在低基数下的偶然成功，导致Rg>100%）的严重干扰。因此，Rg的绝对值高低，并不能直接等同于泛化能力的好坏，但**其剧烈偏离100%的现象本身，就是模型核心策略不稳定的强烈信号**。



##### **5.4.3.2 Upper留存率 (Ru)：知识储备的“保值评估”**

Ru (Pass@k的留存率)则衡量的是模型**潜在的、完整的知识储备**，在面对OOD挑战时的“保值”能力。

- **观察：** 图X中，除OpenAI-o1-mini外，所有箭头的**终点（Ru）**都比其**起点（Rg）**更靠近100%的理想稳定线。
- **推论：** 这一“向心回归”的现象，我们称之为**“推理锚定效应”**。其背后是“大数定律”的必然体现：多次采样通过“平均效应”，系统性地将模型从 Greedy 的“直觉偏差”中拉回，使其表现锚定在本质能力线上。因此，Ru是一个**更稳健、更可信赖**的指标，它更能反映模型由预训练所决定的、内在的、可迁移的知识内核的真实“保值率”。



##### **4.4.3.3 演化路径 (Rg -> Ru)：推理质量的“诊断探针”**

**如果说Ru告诉我们模型“知道多少”，那么从Rg到Ru的演化路径（箭头的长度和方向），则告诉我们模型“如何知道”——即其推理引擎的质量。**

- **“长箭头”特征 (e.g., Numina, Qwen2.5通用模型):**
  - **现象：** Rg与Ru之间存在巨大的鸿沟。
  - **推论：** 这暴露了模型**核心推理能力的相对孱弱**。它们的Greedy策略效率低下，无法稳定地调用其知识储备。其高Ru在很大程度上依赖于**多次采样的“暴力搜索”**，而非精准的、有指导的逻辑推演。这是一种**“知识与策略解耦”**的表现。
- **“短箭头”特征 (e.g., Llama-3.1, o1-mini, DS Distill):**
  - **现象：** Rg与Ru的表现相对一致。
  - **推论：** 这证明了模型拥有一个**更强大、更稳健的核心推理引擎**。它们的“第一反应”有更高的概率就是正确的，因此不需要过度依赖“暴力搜索”来提升性能。这是一种**“知行合一”**的表现。

![](asset/aime_distribution.png)

#### **AIME 2024：非线性“跳跃”背后的数据污染特征**

- **基座模型的异常表现**：Baseline 模型在 AIME 2024 上呈现出极度不符合难度分布的“跳跃得分”现象 。例如，模型能够解出后半段的高难度题目（如第 13、19 题），却无法完成基础的第一题。这种“逻辑孤岛”分布有力地支撑了该数据集在预训练阶段存在“样本记忆”而非“能力泛化”的假说。
- **SFT 阶段的“归纳摩擦”**：在经过监督微调后，SFT 模型虽然掌握了格式规范，却意外丢失了部分基座模型原有的解题能力。这印证了本报告提出的**归纳摩擦（Inductive Friction）**效应：过度的风格对齐可能会压制基座中原本通过记忆存储的稀疏解题经验 。



#### AIME 2025：纯净 OOD 环境下的逻辑稳健增长

- **符合困难梯度的单调性**：在完全分布外（OOD）的 AIME 2025 压力测试中，模型的表现回归了正常的统计规律，即解题成功率随题目难度（由题号表征）呈严格的单调递减 。
- **RL 的“推理锐化”效应**：与 2024 年的波动不同，**DRGRPO** 在 2025 年展现出了近乎完美的“能力前沿”填补能力。强化学习不仅完整覆盖了 SFT 的逻辑路径，还成功攻克了中等难度的中间题目 。这证明了 RL 并非简单注入新知识，而是通过奖励机制实现了逻辑的“内化压缩”与概率分布的“锐化”，将模型潜在的检索潜能转化为了稳定的逻辑输出 。

可以看出，模型在AIME24的正确题目存在明显的**跳变**现象，baseline模型可以做对难度较高的8、9等题，却做不对简单的第一题。而SFT后甚至出现了原本会做的题目反而**遗忘**了的情况，这说明在这些遗失的题目上，SFT学到的推理逻辑甚至与预训练的解题直觉产生了冲突。

而模型在AIME25上的表现则非常正常，合理。做对的题目随训练的研究呈正增长，并没有出现遗忘现象。同时，能够做对的题目难度也层层递进，符合AIME题目由易到难的难度特征。

#### 1. 推理能力的阶段性跨越：从“不可用”到“基础稳健”

数据清晰地展示了模型能力在不同阶段的增长重心。

- **SFT 阶段的爆发力**：模型在基础推理任务上实现了质的飞跃。在 GSM8K* 上，Pass@1 从 **20.9%** 飙升至 **55.2%（+34.3%）**；在 MATH-500 上从 **14.4%** 提升至 **51.6%（+37.2%）**。这表明 SFT 有效激活了模型处理基础数学逻辑的能力。

- **RL 阶段的二次增益**：RL 在 SFT 的基础上进一步压榨了潜力。特别是在 MATH-Test 上，RL 将 Pass@1 从 **44.1%** 推高至 **61.2%（+17.1%）**，显现出强化学习在复杂逻辑搜索中的优势。

  

#### 2. 困难任务的“天花板”突破：Pass@64 的启示

对于极高难度的竞赛级题目，RL 展现了比 SFT 更强的边界突破能力。

- **高难度任务增长更显著**：在 AIME 2024 中，RL（Dr.GRPO）将 Pass@64 从 SFT 的 **26.7%** 提升至 **40.0%（+13.3%）**；AIME 2025 同样实现了从 **23.3%** 到 **36.7%** 的显著跨越。

- **搜索空间的深度挖掘**：这种增长意味着在面对复杂长链推理时，RL 能通过大规模采样和奖励机制引导模型找到那些 SFT 难以通过模仿触达的正确路径。

  

#### 3. 指标错位思辨：知识覆盖与输出稳定性

通过对比模型与 **Instruct（官方充分后训练模型）** 的 Gap，可以揭示当前训练状态的深层本质。

- **知识覆盖已近上限（Pass@64 Gap 极小）**：在 MATH-500 上，RL 模型的 Pass@64 为 **93.6%**，与官方模型的差距仅为 **-0.2%**。在 AIME 2025 上差距也缩小到了 **-3.3%**。这证明模型内部的“知识储备”和“解题潜力”已经非常接近顶尖水平。
- **确定性转化不足（Pass@1 Gap 较大）**：尽管潜力接近，但在“一次性做对”的能力上仍有明显短板。MATH-500 的 Pass@1 差距高达 **-14.0%**。这说明模型虽然“能做对”，但在推理路径的收敛性和确定性上仍显稚嫩，并未能稳定地将搜索到的潜力转化为首选输出。

在所有数学任务中，RL 变体（如 `grpo_no_std_norm`）的起点（$k=1$）均显著高于 SFT 曲线。

- **量化支撑：** 在 MATH-500 任务中，RL 将 $Pass@1$ 从 SFT 的 **51.6%** 推高至 **60.6%**，实现了 **9 个百分点** 的净增长 。而在 AIME 2024 等高难度任务中，$Pass@1$ 的提升更加明显，证明了强化学习在复杂逻辑搜索中的优势。

#### **2.知识边界的“天花板”效应 (The Knowledge Ceiling)**

观察曲线的最右端（$k=64$），一个关键的现象是 SFT 与 RL 曲线表现出了明显的收敛趋势。

- **潜力上限**：在 **MATH-500** 上，SFT 的 $Pass@64$ 已经达到了 **90.6%**，而 RL 的峰值为 **93.6%**，两者差距（3%）远小于 $Pass@1$ 阶段（9%）。
- **结论**：这印证了 **“RL 主要是兑现而非注入知识”** 的假设 。模型解决问题的原始知识库主要在预训练过程中被构建，RL 的核心贡献在于优化了知识的检索与调用效率，而非显著扩展模型能解决问题的绝对边界 。

#### 1. 宏观观测：推理长度的“倒U型”演化与压缩效应	

![](asset/LengthEvolution/correct_length_evolution.png)

在推理能力的演进中，答案正确结果的平均 Token 长度呈现出显著的非线性特征：

- **SFT 阶段（冗余引入）：** 在初期通过引入R1的思维链进行行为克隆微调时，模型在学习到推理模式的同时，往往也会学习到原始数据中的“冗余废话”或死循环模式 。例如，对于GSM8K数据集，从Baseline模型出发经过 SFT 后，Pass@1正确率提升35%的同时，回答正确的平均长度也从 122.8 膨胀至 801.6 。这表明 SFT 虽然激活了能力，但也引入了“冗余=正确”的偏见 。

- **RL 阶段（内化压缩）：** 强化学习（RL）在此充当了“奥卡姆剃刀”的角色 。数据显示，在所有的任务中，RL模型正确回答的平均长度相比SFT阶段均展现出了不同程度的压缩。这说明GRPO在训练过程中成功的“强化”了那些由于逻辑精简可以

- **质变结论：** 模型从 SFT 阶段的“博学但犹豫”进化到了 RL 阶段的“自信且精准”，实现了逻辑密度的显著提升。

  

#### 2.“格式错误”背后的长度长尾效应

观察数据，可以发现答案正确平均长度和格式错误平均长度形成了极其鲜明的对比。

在几乎所有任务中，**“格式错误长度（Fail Avg Token）”都远高于“成功样本长度（Succ Avg Token）”** ，格式错误样本的长度表现出了明确的长尾特征。

以 MATH500 为例，SFT 的成功样本长度均值为 1198.2，而格式错误（Failed）样本的均值却高达 **3747.5**，极其接近 vLLM 的 4096 物理截断上限。这种极端的长度分布并非由于逻辑复杂度的线性增加，而是因为模型陷入了**“逻辑死循环”**（如反复输出 "Wait..."），导致上下文耗尽并在输出最终答案前被物理截断。

## 10. 使用工作流

<a id="section-10"></a>

### 步骤一：准备模型与数据 (Data Preparation)
下载 Bespoke-Stratos 数据集并清洗为 `sft.jsonl`，处理嵌套列表及标签映射。
```bash
python cs336_alignment/setup_model.py

python convert_bespoke_data.py
```

### 步骤二：运行监督微调 (SFT)
让模型学会 `<think>` 思考模式。
```bash
uv run python cs336_alignment/train_sft.py --config configs/sft_config.yaml
```

### 步骤三：运行强化学习 (GRPO)
**关键**: 必须设置环境变量以兼容 vLLM 权重同步。
```bash
export VLLM_USE_V1=0
uv run python cs336_alignment/train_grpo.py --config configs/grpo_config.yaml
```
